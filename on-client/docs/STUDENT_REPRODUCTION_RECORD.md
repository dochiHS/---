> **기록 상태: 초안 · 새 폴더 재현은 아직 수행하지 않음.** 이 문서는 현재 프로젝트 파일과 안내를 읽어 정리한 기록 양식입니다. 학생 진술이나 이 문서만으로 설치·실행·브라우저 동작, 실제 시스템 연결, ALEPH 판정이 확인된 것은 아닙니다. 아래 재현 결과란은 지금 비워 두었으며, 실제로 직접 실행·관찰한 뒤에만 기입합니다.

URL·브랜치·커밋은 추측하거나 이 문서 작성자가 채우지 않았습니다. 비공개 저장소 URL을 대화나 증거에 공개할 필요는 없습니다. 공식 화면의 제출 절차에서 실제 값을 확인하고 저장소·커밋·단계를 다시 대조하세요.

### 기준과 제공 문서의 표기 차이

이 기록의 기준은 `on-client/package.json`에서 읽은 **패키지 버전 `0.2.11`**, **Node.js `24.19.0`**, **npm 스크립트 `start`·`demo`·`check`**입니다. 제공 문서는 수정하지 않았습니다. 확인한 불일치는 다음과 같습니다.

- `docs/FINAL_PRODUCT_GUIDE.md` 제목의 `starter 0.2.9`는 `package.json`의 `0.2.11`과 불일치합니다.
- `docs/AI_SETUP_GUIDE.md`의 `start`·`demo`·`test` 표기는 `package.json`의 `start`·`demo`·`check`와 불일치합니다. `test` 스크립트는 `package.json`에 선언되어 있지 않습니다.
- `docs/STUDENT_LAUNCH_GUIDE.md`의 Node.js `22~24` 표기는 `package.json`이 선언한 정확한 기준 `24.19.0`과 범위 표기가 다릅니다. 실행 기준은 `24.19.0`으로 기록합니다.

이 차이는 기록만 했으며 제공 문서를 고치거나 대체하지 않았습니다. 프로젝트 선언과 실제 PC의 설치 버전은 구분해야 합니다. 이 PC의 Node.js/npm 버전은 직접 실행 후 기입합니다.

`on-client/package-lock.json`을 프로젝트 파일 목록에서 찾지 못했습니다. 따라서 잠금 파일에 기록된 패키지 버전·해시를 대조하지 않았고, 잠금 파일 기반 OSV 조회도 미조회입니다. 이는 취약점 없음이라는 뜻이 아닙니다. 의존성·잠금 파일·조회 설정을 추가하거나 변경하지 않았습니다.

### 운영자 제공 설정 경로와 비밀값

운영자 설정이 필요한 경우 설정 경로는 이 문서에서 **`<운영자가 안내한 설정 파일 경로>`** 같은 자리표시자로만 나타냅니다. 실제 로컬 절대 경로, 설정 내용, 토큰·키·인증서 등 비밀값은 여기에 적지 않습니다. 담당자에게 받은 절차가 있을 때만 사용하고, 설정 파일을 임의로 만들거나 복사하지 않습니다.

## 2. 새 환경 재현 기록

**재현 절차:** 기존 작업 폴더를 보존하고, 공식 제출 화면의 22단계 「비공개 저장소 원문 준비 방법」에 따라 새 폴더를 준비합니다. 공개 저장소를 `git clone`하는 경우에도 제출할 40자리 커밋을 체크아웃했는지 확인합니다. 비공개 저장소 원문 도구의 정확한 명령·도구 경로·출력 경로는 해당 과제 화면의 안내를 따릅니다. 실제 로컬 경로, URL, 해시를 임의로 만들지 않습니다.

새 환경에는 필요한 런타임만 담당 안내에 따라 준비합니다. 기존 폴더의 인증·설정 파일을 무작정 복사하지 않습니다. 프로젝트가 요구하는 Node.js 버전은 `24.19.0`이며 실제 설치 버전은 아래 결과란에 직접 실행 후 기입합니다. `on-client`에서 실행 스크립트를 시작하고 안내된 로컬 주소를 브라우저에서 확인한 뒤, 종료하고 같은 새 폴더에서 다시 실행합니다.

## 4. 데이터 보존·백업·복원 범위

- 기존 작업 폴더와 Git 기록을 지우거나 덮어쓰지 않고, 재현용 폴더를 별도로 만듭니다. 원래 폴더와 새 폴더가 별개인지, 제출할 커밋이 같은지 재현 전에 직접 대조합니다.
- 소스의 재현 기준은 실제로 확인한 Git 커밋입니다. 이 기록을 정리하면서 Git 명령을 실행하지 않았으므로 저장소 여부·origin·브랜치·커밋·변경 상태는 확인하지 않았습니다.
- 개인 인증·SDP/native host 설정은 프로젝트·Git·제출물 밖에 둡니다. 원래 폴더에서 새 폴더로 해당 파일을 무작정 복사하지 않습니다. 필요 경로는 담당자가 안내한 자리표시자 형태로만 문서화하고 실제 경로·비밀값은 기록하지 않습니다.
- 앱이 생성·보존하는 사용자 데이터의 저장 위치와 백업·복원 절차는 현재 읽은 문서만으로 확인하지 못했습니다. 따라서 애플리케이션 데이터가 보존되거나 복구된다고 주장하지 않습니다. 실행 전에 담당자 안내에서 해당 데이터의 위치·보존 기간·백업 및 복원 방법을 확인하고, 승인된 절차만 사용합니다. 이 기록에서는 로컬 데이터 백업·복원을 실행하지 않았습니다.
- 새 폴더 시험의 결과가 확인되기 전까지 원래 작업 폴더를 삭제하거나 교체하지 않습니다. 실패 시에도 기존 커밋과 파일을 먼저 보존하고 원인을 기록합니다.

## 5. 지원 범위·미해결 사항·릴리스 상태

- 이 프로젝트는 로컬 보안 Agent UI 및 서버 시작 틀입니다. 실제 계정·기기·업무 앱·AI 연결은 운영자 설정과 권한이 있을 때만 확인됩니다. `demo` 및 `연결 없음`은 실제 연결이 아닙니다.
- 기기 보안 상태 표시는 악성코드 검사·치료를 의미하지 않습니다. OSV 결과가 없다는 사실도 패키지나 앱 전체의 안전을 보장하지 않습니다.
- AI 설명은 선택 기록의 참고 정보이며 사실 판정이나 조치 집행이 아닙니다. 조치 제안·요청 접수(ACK)만으로 실제 효과가 확인된 것은 아닙니다.
- 19단계 실제 연동 시스템 집행은 공식 과제 안내에서 미완료로 명시되어 있습니다. 따라서 이 기록은 실제 운영 인증 또는 `v1.0` 발행을 뜻하지 않습니다.
- `0.2.11`은 `package.json`에서 확인한 패키지 버전입니다. 21·22단계 원문 재현, 실제 연결, 운영 범위의 완료를 입증하는 릴리스 번호가 아닙니다. `FINAL_PRODUCT_GUIDE.md`의 `starter 0.2.9` 표기는 기준 버전과 불일치한다고 기록했습니다.
- `package-lock.json`을 찾지 못해 잠금 파일 기반 정확한 패키지 버전 대조·OSV 조회는 미조회입니다. 이는 취약점 없음이라는 결론이 아닙니다. 의존성·잠금 파일·조회 설정은 추가하지 않았습니다.
- Node.js 기준은 `24.19.0`, npm 스크립트 기준은 `start`·`demo`·`check`입니다. 제공 문서의 Node.js 범위 및 `test` 스크립트 표기는 각각 기준과 불일치한다고 기록했습니다. 제공 문서는 수정하지 않았습니다.
- Git 원문, 설치 환경, 새 폴더 재현, 단계별 실제 화면은 아직 대조되지 않았습니다.

## 6. 커밋·검증 기록 갱신 방법

이 문서의 재현 결과는 실제 새 환경 실행 후 학생이 기록할 진술입니다. 서버의 AI 원문 검토는 코드·문서의 일관성을 읽어 판단하는 절차이지, 서버가 학생 PC에서 새 환경 실행을 수행했다는 증거가 아닙니다. 최종 제출 전에는 13~22단계의 코드·README·설정 설명·보존 계획·재현 기록을 동일한 제출 원문과 대조하고, 커밋 해시·저장소·단계가 맞는지 공식 화면에서 확인합니다.

> **커밋 기록 유의:** 실행 결과가 나온 뒤 이 문서를 수정해 커밋하면 커밋 해시가 바뀝니다. 따라서 재현한 원문 커밋과 재현 결과 문서를 포함한 제출 커밋을 각각 구분해 적어야 합니다. 공식 화면이 요구하는 “같은 최종 커밋” 조건을 충족하는 실제 절차와 증거 위치는 22단계 제출 화면에서 확인하세요. 새 커밋의 코드를 재현하지 않았다면 그 새 커밋 전체를 재현 성공으로 적지 않습니다.
