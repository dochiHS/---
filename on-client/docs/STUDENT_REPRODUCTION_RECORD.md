### 기준과 제공 문서의 표기 차이

이 기록의 기준은 `on-client/package.json`에서 읽은 **패키지 버전 `0.2.11`**, **Node.js `24.19.0`**, **npm 스크립트 `start`·`demo`·`check`**입니다. 제공 문서는 수정하지 않았습니다. 확인한 불일치는 다음과 같습니다.

- `docs/FINAL_PRODUCT_GUIDE.md` 제목의 `starter 0.2.9`는 `package.json`의 `0.2.11`과 불일치합니다.
- `docs/AI_SETUP_GUIDE.md`의 `start`·`demo`·`test` 표기는 `package.json`의 `start`·`demo`·`check`와 불일치합니다. `test` 스크립트는 `package.json`에 선언되어 있지 않습니다.
- `docs/STUDENT_LAUNCH_GUIDE.md`의 Node.js `22~24` 표기는 `package.json`이 선언한 정확한 기준 `24.19.0`과 범위 표기가 다릅니다. 실행 기준은 `24.19.0`으로 기록합니다.

이 차이는 기록만 했으며 제공 문서를 고치거나 대체하지 않았습니다. 프로젝트 선언과 실제 PC의 설치 버전은 구분해야 합니다. 학생이 보고한 실제 PC 버전은 아래 재현 환경 표에 진술로 기록했으며, 이 문서 작성자가 직접 실행해 확인한 값은 아닙니다.

`on-client/package-lock.json`을 프로젝트 파일 목록에서 찾지 못했습니다. 따라서 잠금 파일에 기록된 패키지 버전·해시를 대조하지 않았고, 잠금 파일 기반 OSV 조회도 미조회입니다. 이는 취약점 없음이라는 뜻이 아닙니다. 의존성·잠금 파일·조회 설정을 추가하거나 변경하지 않았습니다.

## 4. 데이터 보존·백업·복원 범위

### 데이터 대상과 저장 위치

- **코드·문서:** 프로젝트의 소스·학생 코드·문서는 Git 저장소에 보존합니다. 백업·버전 이력은 변경을 검토한 뒤 Git 커밋하고 GitHub에 push하는 방식으로 관리합니다. 이번 재현에서 원문 커밋 이후 변경은 문서만이었다는 내용은 학생 진술이며, 실제 Git diff를 확인한 것은 아닙니다.
- **애플리케이션 SQLite 데이터베이스:** `src/actions/README.md`에 따르면 조치 모듈은 호출자가 지정한 이미 존재하는 애플리케이션 SQLite 파일(`databasePath`)에 조치 관련 `alekov_action_intents`, `alekov_action_state`, `alekov_action_audit` 테이블을 추가합니다. 새 DB를 만들지 않으며 기존 사건·승인·감사 테이블을 읽거나 수정하지 않는다고 안내합니다. 이 저장소의 문서·설정 예시에는 실제 PC의 DB 파일 위치가 확인되지 않으므로 위치는 **`<담당자 확인 필요: 기존 애플리케이션 SQLite DB 파일의 승인된 위치>`**로 둡니다. 이 모듈이 실제 이 재현 환경에서 활성화되었거나 해당 DB가 존재한다고 단정하지 않습니다.
- **그 밖의 앱 데이터:** 사용자·기기·세션·접속 기록 등 다른 런타임 자료의 실제 저장 대상, 파일 또는 데이터베이스 위치와 보존 기간은 읽은 문서에서 특정하지 못했습니다. **`<담당자 확인 필요: 각 앱 데이터의 저장 대상·위치·보존 기간>`**로 남깁니다. SQLite 경로가 확인되지 않았다는 이유로 데이터가 없다고 추정하지 않습니다.
- **운영자 설정·인증 자료:** native host 및 SDP 설정, 인증서·키·토큰은 프로젝트/Git/제출물 밖의 운영자 지정 위치에 둡니다. 실제 위치는 **`<운영자가 안내한 설정 파일 경로>`** 같은 자리표시자로만 적고, 설정·인증 자료를 일반 백업이나 커밋에 포함하지 않습니다.

### 백업 절차

1. 앱을 종료합니다.
2. 담당자가 저장 대상과 승인된 위치를 확인한 뒤, 해당 파일을 원본과 다른 백업 폴더에 날짜를 붙여 복사합니다. 원본을 덮어쓰지 않습니다. SQLite 파일은 앱이 종료된 상태에서만 복사하며, 파일·경로가 확인되지 않았으면 임의로 찾거나 복사하지 말고 담당자에게 확인합니다.
3. 코드·문서는 변경을 확인한 뒤 Git 커밋과 GitHub push로 보존합니다. 운영자 설정·비밀값은 커밋하지 않습니다.

### 복원 절차와 제한

1. 앱을 종료하고, 복원 전에 현재 대상 파일을 별도 위치에 보관합니다.
2. 백업본과 원래 대상 경로가 담당자에게 확인되고 복원이 승인된 경우에만 백업본을 원래 위치로 복사합니다. 앱을 실행한 뒤 필요한 기록이 보이는지 확인합니다.
3. **SQLite 전체 파일 복원은 일반 절차로 실행하지 않습니다.** `src/actions/README.md`는 기존 테이블의 rollback이나 전체 DB 복원을 하지 말라고 명시하고, 조치·학생 기록을 과거 상태로 복원하거나 자동 재집행하지 않도록 안내합니다. 따라서 실제 DB에 조치 이력 등이 있을 수 있으면 담당자의 DB별 복구 절차와 승인을 먼저 확인합니다. 그 절차가 문서로 확인될 때까지 위치·복원 방법을 자리표시자로 남깁니다.
4. 이 백업·복원 절차는 실행해 보지 않았습니다. 이 문서 작성자는 DB 위치·데이터 보존 여부·백업본의 유효성·복원 결과를 확인하지 않았습니다. 운영자 설정이 필요한 데이터는 담당자 안내가 우선이며, 이 계획은 데이터 유실 방지나 복구 가능성을 보증하지 않습니다.
